ResearchTranscript works fully offline: no account, no login, no server, no telemetry. The network-client entitlement is present only because WebKit needs it to render the app's own bundled pages inside the sandbox; the app opens no network connections (verifiable with `nettop`).

Architecture: the UI is a WKWebView. The application logic is written in Python and runs inside the app process through an embedded CPython 3.13 interpreter linked as a framework — no socket, no interpreter child process. The interpreter executes only the scripts shipped in the bundle; the app never downloads code, models or other resources (Guideline 2.5.2). The runtime is reduced to what the app needs: no pip, no venv, no build tooling, no package manager or downloader of any kind. It runs in an isolated configuration (site_import=0, write_bytecode=0) with three fixed search paths inside the sealed bundle. Audio decoding uses AVFoundation; MP3 encoding uses the bundled LAME library (LGPL-2.0+, dynamically linked, its source in Contents/Resources/quellen/lame-4.0.tar.gz and at https://bias.city/researchtranscript/quellen/). Speaker diarisation (SpeakerKit, Core ML) runs in-process. Speech recognition uses one bundled helper, whisper-cli (whisper.cpp, Metal), launched by the app with the sandbox "inherit" entitlement; it reads a temporary WAV file inside the app container and the model file, and terminates with the job.

Three details a static scan may surface, explained up front. (1) The diarisation framework we link (SpeakerKit by Argmax) carries a Hugging Face downloader in its own code; we call it with download disabled and ship every model in the bundle. (2) CPython's standard library includes modules that could load libraries or open sockets (ctypes, urllib); the app uses none of them for that, and Hardened Runtime without any com.apple.security.cs.* exception means library validation refuses code not signed by us. (3) Users may add their own whisper.cpp model files to a folder in their library — neural-network weights read by libwhisper, not executable code, never fetched by the app. The runtime carries no pip, no venv, no build tooling; two checks in our build enforce that.

Files are accessed only through the Open/Save panels, drag and drop, or the library folder the user chooses on first launch (kept as a security-scoped bookmark). The optional e-mail field in the settings is stored in the app's local configuration and written into the change journal of each transcript; exported enrich dossiers and documentation packages carry it over. It is never transmitted. The Zotero integration is optional, read-only, local, and requires the user to pick the Zotero folder.

How to test: the attached zip contains a 2-minute synthetic interview (two invented speakers, synthesised with macOS "say") and its reference text.
1. Launch the app and click "Choose folder …". The panel opens in Documents; create or pick any folder — it becomes the library (kept as a security-scoped bookmark).
2. Drag housing-cooperatives-interview.mp3 into the "AI Transcript" tab, set "Speakers" to 2, click "Start transcription". It takes about 30 seconds on Apple silicon.
3. Click "Edit" on the finished run: the editor shows the transcript with two speakers, a waveform and playback.
4. "Export" writes WebVTT, CSV, text, Markdown, Word, REFI-QDA, an enrich dossier or a documentation package (Word files for researchers) through the Save panel.
5. The Help menu opens a searchable manual in a second window; it is bundled with the app and loads nothing from the network.
